# ADR-040: Per-Lens Digitization Log

**Status:** Accepted
**Date:** 2026-06-01

## Context

The MTF digitizer (ADR-038) produces structured readings for each
reference chart, with a calibration runner that reports aggregate
|Δ| stats. What was missing: a per-lens, human-readable document
showing what the extractor read and how it compares to the eye-read
ground truth.

The optical-specs folder already carries three other per-lens
markdown logs (specs-log, scoring-log, analysis), each with its own
purpose. None of them is a fit for digitization output:

- **specs-log.md** (ADR-031, ADR-033) — provenance of optical and
  physical fields. Hand-written. Records sources checked when the
  diagrams / MTF charts were collected.
- **scoring-log.md** (ADR-022) — rubric application. Hand-written.
  Records the score per optical field with source data and the
  rubric rule applied.
- **analysis.md** (ADR-033) — predictions from construction and MTF
  data. Hand-written. Per-lens commentary.

The digitizer's output is none of those. It's not provenance, not
rubric application, not commentary. It is the literal numerical
result of the pipeline plus diagnostics about that pipeline.

## Decision

A new per-lens file at
`docs/optical-specs/<lens-slug>/digitization-log.md` documents the
MTF digitizer's output for that lens.

### Structure

Every digitization-log starts with a generated-file banner, a brief
intro, and a legend block:

```
<!-- Generated by `py -m mtfdigitizer.log`. ... -->
# Digitization log: <lens-slug>
This lens has N reference panels...
**Legend.**
- EYE — eye-read ground truth from referenceset/charts.py
- EX — what the extractor computed
- Δ — |EX − EYE|; tolerance band ±0.05
- sister-fill — count of samples filled from the sister curve
- · in a sparkline — EYE marked the value as None
```

Then one section per panel (one panel per prime, multiple panels for
zooms like the Tokina 11-18). Each section contains:

1. **Chart metadata** — path, style family, dispatch profile, plot
   box, image height
2. **Sample grid (EYE vs EX)** — per-field stats table, then a
   sparkline block, then four narrow per-field tables (one per
   curve, four columns: frac, EYE, EX, Δ)
3. **Center / edge summary** — values at frac 0.0, 0.9, 1.0
4. **Shape metrics** — peak fraction, peak value, half-falloff
   fraction per curve

Tables in this file are constrained to ≤4 data columns so they
render on phone screens without horizontal scroll.

### File responsibilities

| File                  | Hand-written       | What it captures                        |
| --------------------- | ------------------ | --------------------------------------- |
| `specs-log.md`        | Yes                | Provenance of optical / physical fields |
| `scoring-log.md`      | Yes                | Rubric application per field            |
| `analysis.md`         | Yes                | Predictions and commentary              |
| `digitization-log.md` | **No (generated)** | Pipeline output + diagnostics           |

`digitization-log.md` is the first per-lens file in this folder that
is **generated, not authored**. The banner at the top of the file
states this; the `--check` flag on the writer (see below) catches
hand-edits or stale checkouts.

### Tooling

- `py -m mtfdigitizer.log` writes Tokina lens logs (default scope).
- `py -m mtfdigitizer.log --all` writes logs for every lens that has
  a runnable reference chart.
- `py -m mtfdigitizer.log --check` re-renders in memory, compares to
  the committed file, exits non-zero on any difference or missing
  file. Intended for CI.

### Scope

Logs are only generated for lenses whose reference charts have both
`plot_box` and `ground_truth` populated in
`tools/mtfdigitizer/referenceset/charts.py`. Charts that ship
without ground truth (the digitizer can extract them, but there's
nothing to compare against) get no log. This matches the calibration
runner's scope.

### Multi-panel lenses

Zoom lenses with multiple MTF panels (e.g. Tokina 11-18 with charts
at 11mm and 18mm) get one log with one section per panel. Slug
collapsing: `tokina-atx-m-11-18mm-f2-8-x-at-11mm` and
`tokina-atx-m-11-18mm-f2-8-x-at-18mm` both map to the lens slug
`tokina-atx-m-11-18mm-f2-8-x`.

## Alternatives considered

| Alternative                                                         | Why rejected                                                                                                                                                                     |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| One log per chart (not per lens)                                    | Forces zoom lenses with multiple panels to scatter into separate files; the lens is the natural unit                                                                             |
| Extend `specs-log.md` with the digitizer output                     | Conflates provenance (hand-written, source-of-truth for fields) with pipeline output (generated, refreshable). Same conflation ADR-033 already split apart for specs vs analysis |
| Keep digitizer output only in stdout / the calibration runner       | Loses the audit trail; no per-lens diff when the pipeline changes; no way to review the numbers without running the tool                                                         |
| Generate into a separate top-level directory (`docs/digitization/`) | Splits per-lens artifacts across two trees; harder to grep for "everything about this lens"                                                                                      |

## Consequences

- A new generated file appears under every Tokina lens folder today;
  every lens with reference charts going forward.
- Maintainers must not hand-edit `digitization-log.md`. The banner
  states this; `--check` catches violations in CI.
- The committed log diffs on every pipeline change (algorithm,
  parameters, ground-truth corrections). Diff size is proportional
  to the change — small algorithm tweaks show as small per-row
  numeric differences.
- The four-document-per-lens pattern (specs / scoring / analysis /
  digitization) is established. Future per-lens generated artifacts
  (e.g. a render-match IoU log when ADR-038 §5 lands) can follow
  the same conventions: banner, narrow tables, `--check` for CI.
- Sparkline glyphs use Unicode block characters
  (`▁▂▃▄▅▆▇█`); the digitization-log is the first file in
  `docs/optical-specs/` to depend on non-ASCII glyphs. Markdown
  renderers and the prettier config handle them.
